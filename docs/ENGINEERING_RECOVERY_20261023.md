# Timzee Tech Blog — safe direct-main recovery (2026-10-23)

This changeset intentionally updates **existing main** only, and includes
[skip netlify] [skip ci] to avoid triggering charged or failed hosted builds
on the paused Netlify site. It neither deploys nor makes production writes.

## Correctness and security changes
- Verification queue returns an accurate total-derived \`hasMore\` value instead
  of treating an unrequested count as zero.
- Private verification proof signing requires that the stored path belong to the
  application owner and match the format generated by verify.html. Signed links
  still require a current privileged role and expire after 120 seconds.
- Brevo accepts messages externally before delivery state is finalized internally.
  A database completion failure now attempts quarantine and returns an actionable
  failure if even quarantine cannot be recorded. The worker's sent counter now
  means **recorded** successful completions, not merely provider acceptances.
- Scout diagnostics distinguish healthy, never-run, stale, failed, disabled and
  no-source states. It records latest source-fetch time and timestamps, without
  claiming a paused Netlify scheduler is executing.

## How to verify on an enabled runner (Node 22)
1. Run \`npm ci --ignore-scripts && npm run build && npm test\`.
2. Run \`npx playwright install chromium && npm run test:browser\` in isolated
   staging with correctly scoped test accounts and credentials.
3. Test verification with >25 pending applications and with mismatched owner
   proof metadata. Check negative authorization on ordinary users.
4. Mock Brevo acceptance followed by failed Supabase completion and verify
   quarantine; ensure retries cannot create duplicate provider deliveries.
5. Run the admin Scout health view with a deliberately stale saved timestamp.
   A paused scheduler should say stale, not healthy, without fake activity.
6. Run \`node scripts/verify-public-release.mjs https://YOUR-ISOLATED-PREVIEW
   EXPECTED_40_CHARACTER_COMMIT_SHA\`.
7. Check Supabase security advisor and resolve findings policy by policy.
   Do not blanket-revoke supported public RPCs or disable RLS.
8. Verify storage, auth, community, chat, media, publication, email, and role
   boundaries using separate accounts. Review rollback and backup recovery.

## Explicitly not completed by this commit
- The site remains paused. Netlify scheduled functions cannot run on a paused
  deployment; no change in repository source can resume the hosting plan.
- PR #9's performance work remains a draft and is not merged.
- Real-provider email/AI checks, two-account live E2E, load tests, and the
  full Node/Playwright suite remain unexecuted on this connection.
- Curator publication automation cannot be guaranteed while the host is paused.
- A passing code-level smoke test cannot certify the complete platform or
  prove large-scale readiness.

Release requires confirming the exact deployed commit and re-testing
everything after hosting is available. Preserve all live data and backups.


## Second code pass: stale news imports
The Scout previously calculated the number of old items but still sent them to
\`rankScoutItems\`, which could insert outdated drafts. It now filters known-old
articles **before** ranking/import, applies seven-day age to ordinary stories
and thirty days to time-sensitive opportunities, and handles compact GDELT
timestamps. Missing/malformed timestamps remain drafts for editorial review
rather than being silently discarded. The \`stale_items_skipped\` metric now
reflects actual filtered candidates in the bounded inspected batch.
